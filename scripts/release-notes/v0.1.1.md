修的是三个**装完之后一眼就能看见**的问题。它们都在源码里「看起来没问题」，都通过了当时
的全部测试，然后被发进了 0.1.0 的安装包。

## 修了什么

**1. 标题栏左上角不是应用的图标**

标题栏画的是一个字符 `◈`——而 `◈` 恰好是 `make-icon.mjs` 画的**占位菱形**。所以窗口左上
角的形状，和安装包、exe、任务栏上那张蓝色玻璃旋涡毫无关系。现在标题栏用的是
`build/icon.png` 等比缩到 18px 的副本（`npm run brand` 生成，64px，8 KB，已入库）。

**2. 标题栏拖不动**

`.tb-space` 为了保住一个 tooltip 设了 `-webkit-app-region: no-drag`，可它是 `flex: 1`，
占满品牌名和窗口按钮之间的全部空隙。用 `WM_NCHITTEST` 量 0.1.0 的真实窗口：

```
12% ~ 98% 的采样点 → HTCLIENT（不可拖）
```

整条标题栏只有品牌名左边十几个像素能拖，其余位置按下鼠标什么都不会发生。现在除了右侧
三个窗口按钮，整条都是拖拽区；那个 tooltip 被删掉了——拖拽区里 OS 吞掉鼠标事件，它本来
就永远弹不出来，空间全名在状态栏里已经有一份。

**3. 左下角打印了版本号和路径**

侧边栏底部有一块调试页脚，显示 `nano · chromium 156.0.8078.80` 和 `runtime.json` 的绝对
路径（`C:\Users\<name>\AppData\Local\Temp\...`），默认窗口宽度下还要折成三行。现在这块没有
了。信息没丢：启动日志和 `aragon-browser version` 里都还在。

## 为什么这次它们跑不掉了

三个都是渲染器源码里的事实，而 `npm test` 当时全绿。所以测试补在了**能看见它们的地方**：

- 断言整张样式表**只有一个 `no-drag`**，且必须是 `.win-controls`。把旧规则加回去验证过，
  它会红。
- `brand.png` 与 `build/icon.png` 缩放后的字节逐字比对，标题栏不可能再和真图标漂移。
- `npm run smoke:packaged` 现在用 `@electron/asar` 直接把封装好的 `app.asar` 里的
  `index.html` / `styles.css` / `ui.js` / `brand.png` **抽出来**验——因为这三个报告都来自
  装好的构建，而「源码改对了、dist/ 是旧的」正是它们当初被发出去的方式。
- `scripts/win-hittest.ps1` 是找到第 2 个问题的那把尺子，也留在了仓库里。

## 验证

发布前在**装好的构建**上实际跑过：

- `npm test` — 122 个单元测试
- `npm run smoke` — 53 项真浏览器端到端断言
- `npm run smoke:ui` — 10 项 UI / 几何 / 无边框断言
- `npm run smoke:packaged` — 14 项针对打包产物的断言（含上面三条新增的 asar 检查）
- `scripts/win-hittest.ps1` — 标题栏 9 个采样点全部 `HTCAPTION`
- 启动打包版 → 驱动真实页面 → 抓窗口截图，标题栏是应用图标，左下角没有页脚

## 还没做到的

没有改 Chromium 源码，改造发生在引擎与外部世界的五条边界上（AX 树、跨进程 iframe、
输入事件、元素寻址、进程与存储隔离）。没有代码签名，没有自动更新器，Linux 未验证。
100 MB 的体积来自 Electron 本身。
